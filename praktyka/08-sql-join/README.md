## Крок 1. Як звʼязані таблиці (5 хв)

Відповідь на питання часто розкидана по кількох таблицях. Їх звʼязують **ключі**:
стовпець в одній таблиці містить номер рядка з іншої.

| Звʼязок | Умова для `ON` |
|---|---|
| виконавець → його альбоми | `Album.ArtistId = Artist.ArtistId` |
| альбом → його треки | `Track.AlbumId = Album.AlbumId` |
| жанр → треки цього жанру | `Track.GenreId = Genre.GenreId` |
| клієнт → його рахунки | `Invoice.CustomerId = Customer.CustomerId` |
| співробітник → клієнти, яких він підтримує | `Customer.SupportRepId = Employee.EmployeeId` ⚠️ назви різні |

На [sqlite.org/fiddle](https://sqlite.org/fiddle) (**Load DB…** → `data/chinook.db`) подивіться:

```sql
SELECT * FROM Album LIMIT 3;
SELECT * FROM Employee;
```

✔ В `Album` замість імені виконавця — число `ArtistId`; співробітників — **8**.

<summary>Підказка 1: що з чим — словами</summary>

## Якщо щось пішло не так

| Що бачите | Що це означає | Що робити |
|---|---|---|
| `ambiguous column name: Name` | стовпець з такою назвою є у двох таблицях | писати з таблицею: `t.Name`, `ar.Name` |
| сотні тисяч рядків | у `JOIN` немає `ON` — кожен рядок із кожним | у кожного `JOIN` — свій `ON` |
| `misuse of aggregate: COUNT()` | `COUNT` у `WHERE` | умова на кількість — у `HAVING` після `GROUP BY` |
| один рядок замість багатьох | агрегат без `GROUP BY` | `GROUP BY` за тим, «у кожному» чому |
| пункт 5 — нікого | звичайний `JOIN` | `LEFT JOIN` і `WHERE … IS NULL` |
| пункт 6 — числа в сотні тисяч і мільйони | мілісекунди | `/ 60000.0` |
| `no such column: g.Name` | псевдонім не оголошено | `JOIN Genre g ON …` — після назви таблиці |
| `Не знайдено …chinook.db` | скрипт запущено не з кореня репозиторію | `cd ~/smp-2026` |
| ⏳ хоча запит є | рядок `-- N.` змінено | поверніть рядок як у шаблоні |
