## Крок 1. Пʼять передбачень (10 хв)

Форма «Заявка на відпустку» має пʼять правил:

```
R1  When форма відкрилась                 Then сховати «Причина»; вимкнути «Надіслати»
R2  When змінилось «Днів»   If Днів > 14    Then показати «Причина», зробити обовʼязковим
                                            Else сховати «Причина», зробити необовʼязковим
R3  When змінилось «Згода»  If Згода = так  Then увімкнути «Надіслати»   Else вимкнути «Надіслати»
R4  When натиснуто «Надіслати»  If «Причина» обовʼязкова й порожня
                                            Then повідомити «Заповніть обовʼязкові поля»
                                            Else повідомити «Надіслано керівнику»
R5  When натиснуто «Надіслати»  If Днів > 28  Then повідомити «Потрібне погодження директора»
```

Створіть `praktyka/12-process/peredbachennia.md` і **спершу** запишіть, що побачить людина:

|---|---|

| B | Днів = 20, потім виправили на 5 |
| C | Днів = 5, «Згода» не поставлена, натиснули «Надіслати» |
| D | Днів = 20, «Згода» = так, «Причина» порожня, «Надіслати» |

## Крок 3. Формалізація вашого процесу (40 хв)

Оберіть процес, який **знаєте з життя**: замовлення в кафе, перездача іспиту, оформлення
перепустки, запис до лікаря, видача книжки в бібліотеці, ремонт у гуртожитку.
Заявка на відпустку не підходить — її ми вже розібрали.

Заповніть `process.md` — заготовка вже має розділи:

1. **Опис** — 5–8 речень звичайною мовою;
2. **Учасники** — список «хто — що робить», щонайменше два;
3. **Правила** — щонайменше **5** у формі `When … / If … / Then … / Else …`, з них щонайменше **3 з умовою If**;
4. **Схема** — mermaid прямо в `.md`: щонайменше 5 вузлів, хоча б одна умова `{…}` і підписані гілки `-->|так|`, `-->|ні|`;
5. **SQL і регулярні вирази** — де в цьому процесі знадобився б запит до бази, а де перевірка формату.

```
python praktyka/12-process/perevir.py
```

✔ `perevir.py` перевіряє форму кожного розділу й пише ✅ або що не так. Мінімум — **3 і 4**.
Схему зручно перевірити, вставивши її в [mermaid.live](https://mermaid.live/) — там видно, чи вона малюється.

<details>
<summary>Підказка 1: як знаходити правила</summary>

- Пройдіть процес від початку до кінця й на кожному кроці спитайте: **що стається** (When), **за якої умови** (If), **що робить система** (Then)?
- Подія — це не лише кнопка: «минуло 3 дні», «прийшла оплата», «змінилось поле», «процес дійшов до кроку».
- Хороше правило перевіряється: «якщо днів > 14» — так; «якщо заявка складна» — ні, бо що таке «складна»?

<details>
<summary>Підказка 2: зразок одного правила й шматка схеми</summary>

```

If     на обраний час уже є запис
Then   показати повідомлення «Час зайнятий» і три найближчі вільні
Else   створити запис і надіслати підтвердження
```

```
B{Час вільний?} -->|так| C[Створити запис]
B -->|ні| D[Запропонувати інший час]
```

## Якщо щось пішло не так

| Що бачите | Що це означає | Що робити |
|---|---|---|
| не можу увійти в K2 | обліковий запис, пароль чи мережа | 10 хв максимум — далі запис демонстрації й крок 3 |
| інтерфейс K2 англійською | так і є | **Rules** — правила, **Conditions** — умови, **Actions** — дії; решта — як на демо |
| «правил 0» | рядки правил не починаються з `When` (або `Коли`) | кожне правило — з нового рядка `When …` |
| «у N правил немає Then» | є подія, але немає дії | що саме робить система? |
| «схема — ще шаблон» | у схемі лишились «Дія 1», «Дія 2» | намалюйте свій процес |
| «підписаних стрілок 0» | гілки умови без підписів | підпис «так» / «ні» на стрілці — як у заготовці схеми й підказці 2 |
| схема не малюється на GitHub | помилка синтаксису mermaid | вставте в mermaid.live — він покаже рядок |
| текст вузла з дужками ламає схему | `(`, `)`, `{`, `}` у тексті вузла | беріть текст у лапки: `C["Оплата (картка)"]` |
