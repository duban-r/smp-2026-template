### Три правила, які збережуть вам час

1. Команди вводьте в **терміналі VS Code** (`` Ctrl+` ``) або в **Git Bash**.
2. Файли створюйте й редагуйте **у VS Code**, а не командою `echo`
   у PowerShell — PowerShell пише файли в кодуванні, яке Git вважає бінарним.
3. Назви файлів і гілок — **латиницею**. Повідомлення комітів — українською.

### Про назву гілки

Основна гілка вашого репозиторію називається **`master`**. У тренажері
й на деяких схемах вона зветься `main` — це просто інша назва того самого.
Перевірити, як у вас: `git branch`.

## Крок 5. Шпаргалка і три передбачення (25 хв)

**5.1. Шпаргалка.** Створіть `praktyka/02-git/shpargalka.md` — таблиця
на сім команд: `clone`, `status`, `diff`, `add`, `commit`, `push`, `log`.

```markdown
# Моя шпаргалка Git

| Команда | Що робить — своїми словами | Коли я її використаю |
|---|---|---|
| `git status` | … | … |
```

**Своїми словами, не з документації.**

```
git add praktyka/02-git/shpargalka.md
git commit -m "Додано шпаргалку з команд Git"
```

**5.2. Експеримент з індексом.** Індекс — те, що найчастіше плутають.
Зараз ви перевірите, чи розумієте його, **не підглядаючи у відповідь**.

Створіть `praktyka/02-git/eksperyment.txt` з одним рядком `Рядок 1`:

```
git add praktyka/02-git/eksperyment.txt
git commit -m "Експеримент: початок"
```

Тепер точно в такому порядку:

1. Допишіть у файл `Рядок 2`, збережіть.
2. `git add praktyka/02-git/eksperyment.txt`
3. Допишіть `Рядок 3`, збережіть.
4. **Стоп. Нічого не запускайте.**

Допишіть у `shpargalka.md` розділ `## Передбачення` і дайте відповідь
на три питання — **до** перевірки:

| # | Питання | Чим перевірити |
|---|---|---|
| 1 | У якому розділі — чи розділах — `git status` покаже `eksperyment.txt`? | `git status` |
| 2 | Який рядок покаже `git diff`, а який — `git diff --staged`? | обидві команди |
| 3 | Що потрапить у коміт, якщо зараз зробити коміт **без** `add`? Що покаже `git status` після нього? | `git commit -m "Експеримент: коміт без add"`, потім `git status` і `git show HEAD` |

Тепер перевірте — по одній команді з таблиці. (`shpargalka.md` у `git status`
теж буде: ви щойно дописали в неї передбачення.)

Під кожним передбаченням допишіть: **«Git показав: … Я вгадав / не вгадав,
бо …»**. Помилитись тут не страшно — бали за чесну перевірку, а не за вгадування.

```
git add praktyka/02-git/eksperyment.txt praktyka/02-git/shpargalka.md
git commit -m "Передбачення: як працює індекс"
git push
```

✔ **Кінець другої пари — ви тут.**

## Крок 6. Гілка і злиття (15 хв)

```
git checkout -b dopovnennia
```

У `shpargalka.md` допишіть три рядки таблиці: `branch`, `checkout -b`, `merge`.
Збережіть.

```
git add praktyka/02-git/shpargalka.md
git commit -m "Шпаргалка: команди для гілок"
git checkout master
```

✔ Подивіться на `shpargalka.md` у редакторі — нових рядків **немає**.
Вони не зникли: вони в гілці `dopovnennia`.

Тепер у `README.md` у чеклисті поставте `[x]` біля `praktyka/01-movy`.
Збережіть.

```
git add README.md
git commit -m "Відмічено виконану роботу 1"
git merge dopovnennia -m "Злиття гілки dopovnennia"
git log --oneline --graph
```

✔ `Merge made by the 'ort' strategy.` — і в графі видно розгалуження `|\` і злиття `|/`.
✔ Нові рядки шпаргалки знову на місці.

> **Чому спершу коміт у `master`?** Якщо в `master` нічого не змінилось,
> Git просто пересуне покажчик уперед (*fast-forward*): злиття відбудеться,
> але в історії його не буде видно.

## Крок 7. Конфлікт — навмисно (15 хв)

**Мета:** у `master` зʼявляється розвʼязаний конфлікт злиття у файлі
`praktyka/02-git/pryvitannia.py`.

Що має статись:

1. у `master` — файл з одним рядком `print("Привіт")`, закомічений;
2. гілка `inshe-pryvitannia` змінює цей рядок на `print("Ласкаво просимо!")`;
3. у `master` той **самий рядок** змінюється на `print("Вітаємо, користувачу!")`;
4. злиття гілки в `master` → конфлікт → ви його розвʼязуєте → коміт.

**Спробуйте спершу самі** — усі потрібні команди ви вже використали
на кроках 3–6. Застрягли — розгорніть підказку.

## Якщо щось пішло не так

| Що бачите | Що це означає | Що робити |
|---|---|---|
| `fatal: not a git repository` | ви не в теці репозиторію | `cd ~/smp-2026` |
| `Please tell me who you are` | Git не знає, хто ви | крок 0: два рядки `git config` |
| `error: pathspec 'master' did not match` | ваша головна гілка — `main` | `git branch` → пишіть `main` замість `master` |
| вікно з `~` у стовпчик, клавіші не працюють | відкрився редактор Vim (команда без `-m`) | `Esc`, потім `:wq`, Enter |
| `git log` показав `:` унизу й не повертається | довга історія відкрилась у переглядачі | натисніть `q` |
| `warning: … LF will be replaced by CRLF` | попередження про кінці рядків у Windows | не помилка — ігноруйте |
| злиття є, а в графі гілки не видно | fast-forward: у `master` не було нових комітів | крок 6: спершу коміт у `master`, потім `merge` |
| `push` просить пароль і не приймає | GitHub не приймає пароль із 2021 року | увійти через вікно браузера; не відкрилось — пишіть у чат |
| `! [rejected] … (fetch first)` | на GitHub є коміт, якого у вас немає (правили на сайті) | `git pull --no-rebase --no-edit`, потім `git push` |
| `Binary files differ` для `.md` чи `.py` | файл створено в PowerShell через `echo` | видалити й створити заново у VS Code |
| кирилиця в терміналі — «кракозябри» | так показує консоль Windows | коміти правильні, на GitHub усе нормально; спробуйте Git Bash |
| злякались посеред злиття | — | `git merge --abort` — повернення до стану до `merge` |

який спрацював. Допишіть у шпаргалку, що означає кожен блок вашого
`.gitignore`, — і закомітьте.

**⭐2. Машина часу (15 хв).**

```
git log --oneline
git show HEAD~2
git diff HEAD~3 HEAD
```

Потім навмисно зіпсуйте щось (наприклад, видаліть половину шпаргалки),
закомітьте — і скасуйте:

```
git revert HEAD --no-edit
git log --oneline
```

✔ Зʼявився коміт `Revert "…"`, шпаргалка повернулась. Історію не переписано:
і помилка, і виправлення лишились у ній — так і має бути.

**⭐3. Розширити словник Git (15 хв).** Git дозволяє додавати власні слова
до своєї мови й має вбудовану міні-мову форматування.

```
git config --global alias.graph "log --oneline --graph --all"
git graph
git log --pretty=format:"%h | %ad | %s" --date=short
```

✔ `git graph` працює як нова команда.
Складіть власний формат `--pretty=format:` — хеш, дата, **автор** і повідомлення
([довідка: розділ PRETTY FORMATS](https://git-scm.com/docs/git-log#_pretty_formats)).
Запишіть у шпаргалку, що означає кожен `%`-код, і одним реченням — на що це
схоже з того, що ви знаєте в Python.

**⭐4. Перевірка репозиторію на кожен push (30+ хв).** Справжня задача:
GitHub Actions — ще одна предметна мова, записана в YAML.

Створіть `.github/workflows/perevirka.yml` так, щоб на **кожен push** GitHub:

1. запускав `praktyka/02-git/pryvitannia.py` — і падав, якщо файл не виконується;
2. падав, якщо в репозиторії є хоч один відстежуваний файл `*.env`;
3. падав, якщо в будь-якому `.py` чи `.md` лишився маркер конфлікту
   (`<<<<<<<`, `=======`, `>>>>>>>` на початку рядка).

✔ На GitHub біля коміту — **зелена галочка** (вкладка **Actions** показує кроки).
✔ Навмисно закомітьте файл із рядком `<<<<<<< HEAD` → **червоний хрестик**.
Потім приберіть — знову зелена.

Довідка: [GitHub Actions — швидкий старт](https://docs.github.com/en/actions/writing-workflows/quickstart).

<details>
<summary>Каркас і підказки</summary>

```yaml
name: Перевірка репозиторію
on: push
jobs:
  perevirka:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v5
      - name: Привітання запускається
        run: python3 praktyka/02-git/pryvitannia.py
      # далі — ще два кроки: немає *.env і немає маркерів конфлікту
```

- Крок у `run` падає, якщо команда завершилась з ненульовим кодом.
- `git ls-files '*.env'` виводить відстежувані `.env`-файли; `test -z "…"` успішний, коли рядок порожній.
- `git grep -nE '<регулярний вираз>' -- '*.py' '*.md'` успішний, коли **знайшов** збіг; `!` перед командою інвертує результат.
- У YAML значення, що починається з `!`, беріть у лапки: `run: "! команда"`.
- Команда з `!` має бути **останньою** в кроці `run` — інакше її результат не врахується. Кілька перевірок — кілька окремих кроків.
- Регулярні вирази — тема 5, тож вираз для маркерів — маленький аванс.

</details>
