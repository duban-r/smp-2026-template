## Крок 2. Конфігурація вашого застосунку — JSON (30 хв)

Придумайте застосунок: чат-бот, магазин, гра, розклад — байдуже, але **свій**.
Створіть `praktyka/04-konfihuratsiya/config.json`. Обовʼязково:

| Вимога | Скільки |
|---|---|
| параметрів усього | **8+** |
| вкладений блок (наприклад, налаштування бази чи оплати) | **1+** |
| список | **1+**, з **3+** елементів |
| типи | є **рядок**, **ціле число**, **логічне**; бажано ще дробове |
| рядок, схожий на число (версія `1.10`, телефон, поштовий індекс) | **1** — навмисно, для кроку 3 |

Нагадування синтаксису JSON: ключі й рядки — **тільки подвійні лапки**,
після останнього елемента **немає коми**, коментарів **немає**.


## Крок 3. Те саме — YAML і TOML (25 хв)

Створіть `config.yaml` і `config.toml` з **тими самими** значеннями.

Потім перевірте всі три одразу:

```
python praktyka/04-konfihuratsiya/perevir.py praktyka/04-konfihuratsiya/config.json praktyka/04-konfihuratsiya/config.yaml praktyka/04-konfihuratsiya/config.toml
```

✔ У трьох блоках виводу **однакові значення й однакові типи**. Особливо
перевірте рядок, схожий на число: у YAML він мусить лишитись **рядком**.

<details>
<summary>Підказка: чим YAML і TOML відрізняються від JSON</summary>

- **YAML:** без дужок і ком; вкладеність — відступом у 2 пробіли; список —
  рядки з `- `; рядок, схожий на число чи на `yes/no/on/off`, — **у лапках**.
- **TOML:** рядки **завжди** в лапках; список — `["a", "b", "c"]`;
  вкладений блок — окремий розділ `[database]` **в кінці файлу**, після простих параметрів.

</details>

```
git add praktyka/04-konfihuratsiya/config.yaml praktyka/04-konfihuratsiya/config.toml
git commit -m "Конфігурація застосунку: YAML і TOML"
```

## Якщо щось пішло не так

| Що бачите | Що це означає | Що робити |
|---|---|---|
| `python` відкриває Microsoft Store або «не знайдено» | Python не встановлений або не в PATH | крок 0: інсталятор з галочкою «Add python.exe to PATH»; або `py` замість `python` |
| `No module named yaml` / `Немає бібліотеки PyYAML` | PyYAML не встановлено | `python -m pip install pyyaml` |
| `No such file or directory: 'praktyka/...'` | ви не в корені репозиторію | `cd ~/smp-2026` |
| JSON: `Illegal trailing comma before end of object` | кома після останнього елемента | прибрати кому перед `}` або `]` |
| JSON: `Expecting property name enclosed in double quotes` | одинарні лапки або кома в кінці | тільки `"подвійні"` |
| YAML: `found character '\t' that cannot start any token` | табуляція замість пробілів | замінити на 2 пробіли; у VS Code — `Spaces: 2` |
| YAML: `mapping values are not allowed here` | зайвий пробіл у відступі або двокрапка всередині значення | вирівняти відступ; значення з `:` — у лапки |
| TOML: `Invalid value` | рядок без лапок | `name = "rozklad-bot"` |
| TOML: `Expected '=' after a key` | пропущено `=` | `port = 8080` |
| у YAML тип інший, ніж у JSON | YAML «вгадав» тип | взяти значення в лапки |
| `git diff` нічого не показує | файл не збережено | `Ctrl+S` |

<summary>Підказка</summary>

у режимі `"rb"`. Усі три повертають звичайний словник, а словники можна
порівнювати через `==`.

</details>

**⭐3. Одна конфігурація — два середовища (15 хв).** Мова YAML уміє не повторюватись.

```
python praktyka/04-konfihuratsiya/perevir.py praktyka/04-konfihuratsiya/sredovyshcha.yaml
```

✔ У виводі в обох середовищах є всі базові параметри, хоча у файлі вони записані один раз.

<details>
<summary>Підказка</summary>

Якір і злиття: `bazovi: &bazovi` … потім у середовищі `<<: *bazovi`
і нижче — лише ті параметри, що відрізняються.

</details>

**⭐4. Мова, яка описує вашу конфігурацію (30+ хв).** Справжня задача:
**JSON Schema** — предметна мова для опису того, якою **має бути** конфігурація.
Нею VS Code підказує поля в `package.json` і `docker-compose.yml`.

1. `praktyka/04-konfihuratsiya/schema.json`: обовʼязкові ключі вашої конфігурації,
   їхні типи, порт у межах 1–65535, список щонайменше з 3 елементів.
2. `praktyka/04-konfihuratsiya/validuvaty.py`: перевіряє **всі три** файли за схемою
   й друкує ✅ або всі знайдені помилки.
3. Навмисно зіпсуйте `config.toml` (порт рядком) — скрипт має це показати.

```
python -m pip install jsonschema
```

Довідка: [Understanding JSON Schema](https://json-schema.org/understanding-json-schema).

<details>
<summary>Підказки</summary>

- Схема — теж JSON: `{"type": "object", "required": [...], "properties": {"port": {"type": "integer", "minimum": 1, "maximum": 65535}}}`.
- `from jsonschema import Draft202012Validator` → `Draft202012Validator(schema).iter_errors(dani)` віддає всі помилки; у кожної є `.path` і `.message`.

</details>
